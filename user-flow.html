How an order moves through Lakun

A customer in an apartment building lists what they need. Nearby shops bid a price, the customer picks one and pays by bank transfer or Telebirr, operations verify the payment and pay the shop, and a rider brings the items to the door. Four roles, one shared order record.

Customer

Requests items, compares shop prices, pays, tracks the delivery and confirms receipt.

Demo: 08011111111
Vendor (shop)

Sees requests in range, submits a price before the window closes, approves pickup when packed.

Demo: 08055555555
Admin (operations)

Forwards bids, verifies payment proof, pays the vendor, assigns riders, manages the platform.

Demo: 08000000000
Delivery rider

Buys task credits, receives assignments, picks up from the shop and delivers to the door.

Order status

Status lifecycle

Every screen reads and writes the same orders.status field. The colour of each stage shows who moves the order forward. Click a stage to jump to its step.

Customer action Vendor action Admin action Rider action
No bids in the windowThe order ends as cancelled. Admin can re-open bidding from the orders board, which puts it back into bidding.
Payment proof rejectedAdmin rejects the screenshot or transaction ID, and the order moves to failed_payment. The customer is notified.
Rider has no creditsEach assignment costs 1 credit, so a rider with 0 can't be assigned. They top up from a credit package on My credits.
